    Company and container data¶

    Small optional files tell the mod when a company is open, whether it has a reach stacker for containers, and what a container cargo is. They work for every map and every cargo mod: the files sit next to the files the game already loads. The examples in the def/ folder of this package show the format.

    1. Company files¶

    Same folder and same name as the company files of the game, only with .v3def:

    all cities    /def/company/your_company.sui
           -> /def/company/your_company.v3def

    one city      /def/company/your_company/editor/your_city.sii
           -> /def/company/your_company/editor/your_city.v3def

    The city file name is the city token (the editor file name up to the first dot). A city file replaces the working hours of the company file in that city, and a container_load line in a city file applies to that city only (e.g. a company that has a reach stacker at just one of its sites).

    1a. Working hours¶

    working_time :
{
monday: (06.00, 22.00)
saturday: (07.00, 12.00);(13.00, 16.00)
sunday: closed
}
    • days: monday tuesday wednesday thursday friday saturday sunday
    • one or more time spans (hh.mm, hh.mm), several separated by ;
    • 24.00 = end of the day; an end at or before the start runs past midnight, e.g. (22.00, 06.00)
    • closed = closed all day
    • a missing day = open all day
    • no file or no working_time block = the company is always open

    While a company is closed, its offers are hidden, no new cargo is generated there, and its company point shows that it is closed together with the working hours.

    Special transports (oversize) can have their own hours in the same file:

    working_time_oversize :
{
monday: (07.00, 16.00)
saturday: closed
sunday: closed
}
    • same format as working_time
    • used for loading (start) and unloading (destination) of special transports; missing block = working_time applies
    • a special transport offer only appears if it can be loaded now, driven (50 km/h on average, at most 10 h driving per 24 h, 45 min break after 4.5 h) and unloaded in these hours before Friday 15:00 (no oversize driving Fri 15:00 - Mon 09:00)

    1b. Reach stacker (containers)¶

    container_load: truereach stacker: container cargo is given out to own container chassis, a container is lifted off on delivery
    container_load: falseno reach stacker: no container cargo for own container chassis, the container stays on the chassis

    Companies without the line: the cargo market is not changed; on delivery the company counts as without reach stacker (container stays).

    What happens with an own container chassis:

    • A container is lifted on and off only where the company has a reach stacker.
    • Delivered at a company without reach stacker, the container stays on the chassis. The chassis then works like the trailer type of the container (see 2.), with the empty weight and inner volume of the container, and the cargo market offers cargo for that trailer type.
    • Directly after unloading there, the cargo market of that company also offers "Empty container" back to one of the 10 nearest companies with reach stacker: low pay, no loading. The offer is valid as long as the truck stays on the company yard.
    • A cargo carried in the container to a company with reach stacker takes the container off the chassis.

    1c. Cargo filters¶

    Blocks with one cargo per line, written as the cargo_data name of the game (cargo.<name>, as in the cargo .sui):

    ignore_in :                  cargo the company never receives
{                            (cargo market and trailer jobs)
cargo.air_mails
}
ignore_out :                 cargo the company never sends
{ ... }

    freight_market: false        no cargo market offers for own trailers at this
                             company ("Cargo market" / "External cargo
                             market"); the company also never loads cargo
                             onto a trailer that is not its own
freight_market_ignore_in : { ... }    only for the cargo market
freight_market_ignore_out : { ... }

    semi_trailerjob_in: false    no trailer jobs ("Freight market", trailer is
semi_trailerjob_out: false   provided) to / from this company
semi_trailerjob_ignore_in : { ... }   only for trailer jobs
semi_trailerjob_ignore_out : { ... }
    • only false is allowed for freight_market / semi_trailerjob_in / _out; a missing line = the game lists in full
    • the filters add to each other (e.g. ignore_out and semi_trailerjob_ignore_out)
    • what arrives at a company is decided only by its in folder of the game and these filters

    1d. Trailer jobs: what happens at the destination (return trips)¶

    For trailer jobs the destination company decides per body type of the trailer what happens after arrival:

    semi_trailerjob_return_full :    unload, load return cargo at this company,
{                                drive back to the sender
curtainside
dryvan
}
semi_trailerjob_return_empty :   unload only; the return cargo is loaded at
{                                the nearest fitting company (same city
fueltank                         first, else outside), otherwise back empty
lowbed
}
semi_trailerjob_drop: true       pure drop yard (e.g. unaccompanied trailers
                                 for ferry or rail): every trailer is only
                                 parked, the job ends there
trailer_hub: true                transshipment point (rail or ferry
                                 terminal): as SENDER it takes back loaded
                                 trailers, the return cargo does not have to
                                 be in its in list

    Body type without entry: curtainside, dryvan, refrigerated, insulated, flatbed, container, flatbed_cont = return_full; every other body type (tanks, silo, tipper, low loader, logs, livestock, car transporter ...) = return_empty. Rule of thumb: return_full for a special body only where the company loads the same body itself (quarry - tipper, sawmill - logs, car terminal - car transporter); low loaders always return_empty.

    Return cargo:

    • loaded like the cargo market of the game loads a trailer that is not the company's own: the cargo must fit the trailer (body type, volume, weight), the loading company must be allowed to send it (ignore_out, freight_market rules; semi_trailerjob_out does not apply, the company only loads), the sender must accept it (its in list, ignore_in, semi_trailerjob rules) unless the sender is a trailer_hub
    • chosen at random with the cargo weights of the game, fixed per offer
    • containers: loading company with container_load: true - the container is lifted off and any container cargo goes onto the chassis; with container_load: false - the container stays, a box container is loaded with cargo of its body type, a special container (body_type = cargo name, see section 2) only with that cargo
    • the destination company never gives back the cargo it has just received
    • the whole trip is one job: one delivery time at the sender, paid at the sender: outbound + return cargo; an empty run (destination - loading company, or back empty) is paid like an empty container: 10 % of the units of the outbound cargo per km

    The job list shows the trip as Start > Destination > (2nd company >) Start, the return cargo in blue after the outbound cargo, and the total distance, time and pay. A city file can hold the same lines for one city (a block in the city file goes first for its body types).

    1e. Waiting times¶

    wait_time :
{
load: 30-180
unload: 30-180
pickup: 5-20
drop: 5-15
}
wait_factors :
{
1.5 : (06.00, 08.00);(12.00, 13.00)
0.7 : (22.00, 06.00)
}
    • load = loading, unload = unloading, pickup = taking over a prepared loaded trailer, drop = parking the trailer at a pure drop yard (T)
    • minutes from-to; each check-in rolls a random time in between
    • wait_factors: factor = time spans (hh.mm or hh:mm), several spans with the same factor separated by ; an end at or before the start runs past midnight; outside all spans the factor is 1.0
    • a missing line or block uses the city file, then the company file, then the default: load/unload 30-180, pickup 5-20, drop 5-15, factors 06-10 x1.5, 16-22 x0.7, 22-06 x0.5

    The waiting time sits between confirming (choosing the parking difficulty on delivery, Enter on the loading/unloading bay with an own trailer, or the loading tile) and the bay/trailer being released. On check-in a message shows the expected time. Leaving the company premises cancels the check-in. While waiting, stop on the premises and switch the engine off: a hint offers a rest until the end of the waiting time. On release everything continues by itself.

    1f. Bays per body type (parking difficulty)¶

    A company can keep bays of one difficulty free of certain body types, e.g. no low loaders at the loading docks (hard bays):

    lanes_hard_ignore :          body types (body_type of the trailer, without
{                            prefix) that never load or unload on a hard bay
lowbed
lowboy
}
lanes_medium_ignore : { ... }   the same for medium bays
lanes_easy_ignore : { ... }     the same for easy bays
    • applies to every job type at this company: cargo market, driver jobs, trailer jobs and return cargo
    • loading: if the loading bay of the job is on a blocked difficulty, the job gets a free allowed loading bay of the company (fitting length, not occupied); if there is none, the bay of the game stays
    • unloading: blocked difficulties cannot be chosen
    • cargo market: if the loading company has no allowed loading bay or the destination has no allowed unloading bay for the trailer, there is no offer for it
    • the body type is the one of the trailer that is attached
    • fixed in the DLL, at every company: low loaders (lowbed, lowboy) only on easy bays; medium, hard and loading points without difficulty (e.g. docks) are always blocked for them; except trailer hubs (trailer_hub: true), where trailers are only dropped
    • a city file can hold the same blocks; they add to the company file

    1g. Partial loads and tour planning (cargo market, own trailer)¶

    A company can offer and accept partial loads in the cargo market:

    units_out :                  units this company SENDS per cargo
{
default: 1-max               any amount up to a full load
cargo.furniture: 1-6         this cargo only 1 to 6 units
cargo.cement: max            this cargo only as a full load
}
units_in : { ... }           the same for what this company RECEIVES

    load_mix_out :               how often a full or a partial load is offered
{                            (weights, any numbers)
default :
{
full: 60
partial: 40
}
cargo.furniture :
{
full: 20
partial: 80
}
}
load_mix_in : { ... }        the same on the receiving side
    • values: a number, from-to (e.g. 1-6), or max (= a full load)
    • a cargo.<name> line goes first, otherwise default applies
    • a city file replaces the whole block of the company file in that city
    • no units block at sender and receiver = full loads only, as in the game; a block on one side only = the other side takes full loads only
    • no load_mix block = full and partial half and half
    • tour and mixed in load_mix are reserved for a later version
    • a partial load is less than the minimum filling of the trailer (cargo_min_fill of the body type in /def/economy_trailers_data/, game default 0.8); the amount is limited to what still fits on the trailer
    • cargo with load_unit: whole (see README of the cargo data) is never offered as a partial load

    Adding cargo and tour planning with partial loads:

    • "Set as GPS destination" on a cargo market offer reserves it (also before anything is loaded); taking an offer on the company yard adds it to the trip; at most 8 jobs and reservations together
    • every job and reservation takes its share of space and weight; the cargo market then only shows offers that still fit: space, weight, temperature / food / dangerous goods, delivery times, and the area: from the second cargo on, the sender AND the receiver of a new offer must each lie within 100 km (road) of a sender or receiver already in the trip (also abroad); the first cargo is free
    • a fully planned trailer locks the cargo market until a part is delivered or a reservation is cancelled
    • the active job (GPS) is the player's choice (right-click on a job tile in the main menu, or "Drive here next" in Current job), otherwise the nearest destination first unless another job would then miss its delivery time
    • the trip and the reservations are saved with the save game

    2. Container cargo¶

    Same folder and same name as the model_area file of the container cargo, only with .v3def, one file per container size:

    /def/vehicle/cargo/your_cargo_c/model_area_20.sii
-> /def/vehicle/cargo/your_cargo_c/model_area_20.v3def
/def/vehicle/cargo/your_cargo_c/model_area_40.sii
-> /def/vehicle/cargo/your_cargo_c/model_area_40.v3def

    body_type: dryvan        container for any cargo of this trailer type
                         while it stays on the chassis (dryvan,
                         refrigerated, insulated, or foodtank for a food
                         tank container)
body_type: <cargo name> special container made for exactly one cargo
                         (e.g. dangerous goods tank containers - fuel,
                         chemicals, gas - whose plates belong to the
                         cargo): the body type has the
                         SAME name as the cargo (its cargo .sui and this
                         folder). It is only loaded again with this cargo,
                         never by the company that just received it
                         (another company loads it, otherwise it goes back
                         empty). Any other name is reported in the log.
body_type: none          no follow-up cargo at all: the container can only
                         be returned empty
body_mass: 2200          empty weight of the container in kg
volume: 33               inner volume in m3

    Missing file or missing line - default values:
  body_type  dryvan
  body_mass  20 ft 2200 kg, 40 ft 3750 kg  (refrigerated: 3000 / 4800 kg)
  volume     20 ft 33 m3,   40 ft 67 m3    (refrigerated: 28 / 59 m3)
20 ft or 40 ft comes from the model size (longer than 9 m = 40 ft).

    Icon for "Return container"¶

    File: def/vehicle/cargo/<your_cargo_c>/accessory_container_<size>_<color>.v3def (same name as the accessory .sii, ending .v3def)

    empty_icon: "/material/ui/cargo_icons/<your_icon>.mat"

    The .mat must be in /material/ui/cargo_icons/ (like every cargo icon, 122 x 96 px, transparent). It is shown in the cargo market and the job info for the "Return container" offer of this container. Missing file - the mod icon for a 20 ft / 40 ft box or tank container is used.

    3. Country file (driver wage)¶

    Same folder and same name as the country file of the game, only with .v3def:

    /def/country/your_country.sui
-> /def/country/your_country.v3def

    driver_wage :
{
hourly_net_wage: 11.13
daily_allowance: 28
bonus_max: 25
allowance_tier[]: 8 0.5
allowance_travel[]: 0 0.5
}
    • hourly_net_wage: net wage per working hour; a driver tour pays at most 10 working hours per calendar day and 48 hours per tour (a tour lasts at most 4 days + 8 hours)
    • daily_allowance: allowance for one full day of absence
    • the tour starts when it is taken and ends with the delivery report; calendar days in game time. Full days between the first and the last day always count full. How much the first/last day and a one-day tour get depends on the country:
    • allowance_tier[]: hours share - one-day tour (start and end on the same calendar day): the share applies to MORE than these hours, the highest matching line counts; 0 = any duration. No line = nothing. allowance_tier[]: 8 0.5 (more than 8 h: half a day)
    • allowance_travel[]: hours share - first and last day of a tour over several days, hours counted on that day; missing = as allowance_tier. allowance_travel[]: 0 0.5 (always half a day)
    • allowance_meal[]: hh:mm share / night share - instead of hours: the share counts if the meal time lies within the tour on that day, night = a night spent away (not on the last day); at most 1 per day. Lines of allowance_meal replace the hour lines. allowance_meal[]: 13:00 0.333 allowance_meal[]: night 0.334
    • allowance_same_day: 0 = a one-day tour gets no allowance
    • the lines of a list replace the mod's lines for this country (all lines of that list, not single ones). Shares 0 ... 1.
    • no allowance = no allowance line in the delivery report
    • bonus_max: highest pay above the rate in percent; each start company rolls its own bonus per game week (most pay the rate), 0 = never
    • the country of the company where the tour starts decides
    • missing file or line: the mod's value for this country is used (lphd_land_v3def.zip holds them for all countries)

    Driver tours (quick jobs) pay wage and allowance instead of the cargo pay. Fuel is paid by the employer (game), deductions for cargo damage or delay are taken over by the employer.

    Format¶

    key: value
    • one entry per line, spaces or tabs around the colon are allowed
    • lines starting with # or // are comments, a # after the value too
    • numbers with decimal point, no units on the line
    • a line with a wrong value is reported in game.log and ignored

    Example files¶

    All examples for download: resources_company_data.zip

    def/company/your_company.v3def 
    # Fleet & Road Realism - Firmendaten (Standard fuer alle Staedte dieser Firma) / company data (default for all cities of this company)
# Datei / file: /def/company/your_company.v3def  (neben / next to /def/company/your_company.sui)
# Ueber jedem Eintrag steht die Beschreibung (# ...), der Eintrag selbst steht ohne #.
# Above each entry is its description (# ...), the entry itself has no #.
# Alle Moeglichkeiten: README_company_data.txt / all options: README_company_data.txt

# Reachstacker vorhanden? true = Container auf-/absetzen, false = Container bleibt auf dem Chassis
# Reach stacker on site? true = containers are lifted on and off, false = the container stays on the chassis
container_load: false

# Oeffnungszeiten (Spielzeit), fehlender Tag = ganzen Tag offen, closed = geschlossen
# Working hours (game time), missing day = open all day, closed = closed all day
working_time :
{
monday: (06.00, 22.00)
tuesday: (06.00, 22.00)
wednesday: (06.00, 22.00)
thursday: (06.00, 22.00)
friday: (06.00, 22.00)
saturday: (06.00, 12.00)
sunday: closed
}

# Fracht, die diese Firma nie annimmt (cargo.<name> aus der Fracht-.sui, eine je Zeile)
# Cargo this company never receives (cargo.<name> from the cargo .sui, one per line)
ignore_in :
{
cargo.air_mails
}

# Auflieger-Auftraege mit dieser Firma als Ziel: je Aufbau Rueckfracht hier laden (full) oder woanders / leer (empty)
# Trailer jobs with this company as destination: per body type load return cargo here (full) or elsewhere / empty (empty)
semi_trailerjob_return_full :
{
curtainside
dryvan
}
semi_trailerjob_return_empty :
{
fueltank
lowbed
}

# Aufbauten, die nie auf schweren / mittleren Spuren laden oder entladen
# Body types that never load or unload on hard / medium bays
lanes_hard_ignore :
{
lowbed
lowboy
}
lanes_medium_ignore :
{
lowbed
lowboy
}

# Wartezeiten in Minuten von-bis (zufaellig dazwischen)
# Waiting times in minutes from-to (random in between)
wait_time :
{
load: 30-180
unload: 30-180
pickup: 5-20
drop: 5-15
}

# Faktor auf die Wartezeit je Tageszeit (ausserhalb der Spannen 1.0)
# Factor on the waiting time per time of day (outside the spans 1.0)
wait_factors :
{
1.5 : (06.00, 08.00);(12.00, 13.00)
1.3 : (14.00, 15.00)
0.7 : (22.00, 06.00)
}

# Teilladungen: Einheiten, die diese Firma verschickt (Zahl, von-bis oder max = volle Ladung; cargo.<name> vor default)
# Partial loads: units this company sends (number, from-to or max = full load; cargo.<name> before default)
units_out :
{
default: 1-max
cargo.furniture: 1-6
}

# Teilladungen: Einheiten, die diese Firma annimmt
# Partial loads: units this company receives
units_in :
{
default: 1-max
}

# Wie oft volle Ladung, Teilladung, Tour (mehrere Empfaenger) bzw. Mischladung (mehrere Frachten
# zu einem Empfaenger) angeboten wird (Gewichtung); ohne Block = halb und halb, ohne tour/mixed keine
# How often a full load, partial load, tour (several receivers) or mixed load (several cargos to one
# receiver) is offered (weights); no block = half and half, without tour/mixed none
load_mix_out :
{
default :
{
full: 50
partial: 30
tour: 10
mixed: 10
}
}
