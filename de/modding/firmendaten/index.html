    Firmen- und Containerdaten¶

    Kleine optionale Dateien sagen der Mod, wann eine Firma offen ist, ob sie einen Reachstacker für Container hat und was eine Containerfracht ist. Sie funktionieren mit jeder Karte und jeder Fracht-Mod: die Dateien liegen neben den Dateien, die das Spiel ohnehin lädt. Die Beispiele im Ordner def/ dieses Pakets zeigen das Format.

    1. Firmen-Dateien¶

    Gleicher Ordner und gleicher Name wie die Firmen-Dateien des Spiels, nur mit .v3def:

    alle Städte   /def/company/your_company.sui
           -> /def/company/your_company.v3def

    eine Stadt    /def/company/your_company/editor/your_city.sii
           -> /def/company/your_company/editor/your_city.v3def

    Der Name der Stadt-Datei ist das Stadt-Token (Name der Editor-Datei bis zum ersten Punkt). Eine Stadt-Datei ersetzt in dieser Stadt die Öffnungszeiten der Firmen-Datei, und eine container_load-Zeile in einer Stadt-Datei gilt nur für diese Stadt (z. B. eine Firma, die nur an einem Standort einen Reachstacker hat).

    1a. Öffnungszeiten¶

    working_time :
{
monday: (06.00, 22.00)
saturday: (07.00, 12.00);(13.00, 16.00)
sunday: closed
}
    • Tage: monday tuesday wednesday thursday friday saturday sunday
    • eine oder mehrere Zeitspannen (hh.mm, hh.mm), mehrere getrennt durch ;
    • 24.00 = Ende des Tages; ein Ende vor oder gleich dem Anfang läuft über Mitternacht, z. B. (22.00, 06.00)
    • closed = ganzen Tag geschlossen
    • fehlender Tag = ganzen Tag offen
    • keine Datei oder kein working_time-Block = die Firma ist immer offen

    Solange eine Firma geschlossen ist, sind ihre Angebote ausgeblendet, es wird dort keine neue Fracht erzeugt, und ihr Firmenpunkt zeigt "geschlossen" mit den Öffnungszeiten.

    Schwertransporte (oversize) können in derselben Datei eigene Zeiten haben:

    working_time_oversize :
{
monday: (07.00, 16.00)
saturday: closed
sunday: closed
}
    • gleiches Format wie working_time
    • gilt für das Laden (Start) und Entladen (Ziel) von Schwertransporten; fehlender Block = working_time gilt
    • ein Schwertransport-Angebot erscheint nur, wenn es jetzt geladen, gefahren (50 km/h im Schnitt, höchstens 10 h Fahrt je 24 h, 45 min Pause nach 4,5 h) und in diesen Zeiten vor Freitag 15:00 entladen werden kann (keine Schwertransporte Fr 15:00 - Mo 09:00)

    1b. Reachstacker (Container)¶

    container_load: trueReachstacker: Containerfracht wird an eigene Container-Chassis vergeben, ein Container wird beim Abliefern abgehoben
    container_load: falsekein Reachstacker: keine Containerfracht für eigene Container-Chassis, der Container bleibt auf dem Chassis

    Firmen ohne die Zeile: der Frachtmarkt bleibt unverändert; beim Abliefern gilt die Firma als ohne Reachstacker (Container bleibt).

    Was mit einem eigenen Container-Chassis passiert:

    • Ein Container wird nur dort auf- und abgesetzt, wo die Firma einen Reachstacker hat.
    • Bei einer Firma ohne Reachstacker abgeliefert, bleibt der Container auf dem Chassis. Das Chassis arbeitet dann wie der Aufliegertyp des Containers (siehe 2.), mit Leergewicht und Innenvolumen des Containers, und der Frachtmarkt bietet Fracht für diesen Aufliegertyp an.
    • Direkt nach dem Entladen dort bietet der Frachtmarkt dieser Firma auch "Leercontainer" zurück zu einer der 10 nächsten Firmen mit Reachstacker an: wenig Lohn, kein Beladen. Das Angebot gilt, solange der Lkw auf dem Firmenhof bleibt.
    • Eine Fracht, die im Container zu einer Firma mit Reachstacker gefahren wird, nimmt den Container vom Chassis.

    1c. Frachtfilter¶

    Blöcke mit einer Fracht je Zeile, geschrieben als cargo_data-Name des Spiels (cargo.<name>, wie in der Fracht-.sui):

    ignore_in :                  Fracht, die die Firma nie annimmt
{                            (Frachtmarkt und Auflieger-Aufträge)
cargo.air_mails
}
ignore_out :                 Fracht, die die Firma nie verschickt
{ ... }

    freight_market: false        keine Frachtmarkt-Angebote für eigene Auflieger
                             bei dieser Firma ("Frachtmarkt" / "Externer
                             Frachtmarkt"); die Firma lädt auch nie Fracht
                             auf einen Auflieger, der nicht ihr eigener ist
freight_market_ignore_in : { ... }    nur für den Frachtmarkt
freight_market_ignore_out : { ... }

    semi_trailerjob_in: false    keine Auflieger-Aufträge ("Frachtaufträge",
semi_trailerjob_out: false   Auflieger wird gestellt) zu / von dieser Firma
semi_trailerjob_ignore_in : { ... }   nur für Auflieger-Aufträge
semi_trailerjob_ignore_out : { ... }
    • für freight_market / semi_trailerjob_in / _out ist nur false erlaubt; fehlende Zeile = das Spiel listet vollständig
    • die Filter addieren sich (z. B. ignore_out und semi_trailerjob_ignore_out)
    • was bei einer Firma ankommt, entscheiden nur ihr in-Ordner im Spiel und diese Filter

    1d. Auflieger-Aufträge: was am Ziel passiert (Rückfahrten)¶

    Bei Auflieger-Aufträgen entscheidet die Zielfirma je Aufbau des Aufliegers, was nach der Ankunft passiert:

    semi_trailerjob_return_full :    entladen, Rückfracht bei dieser Firma
{                                laden, zurück zum Absender
curtainside
dryvan
}
semi_trailerjob_return_empty :   nur entladen; die Rückfracht wird bei der
{                                nächsten passenden Firma geladen (zuerst
fueltank                         in der Stadt, sonst ausserhalb), sonst leer
lowbed                           zurück
}
semi_trailerjob_drop: true       reiner Abstellplatz (z. B. unbegleitete
                                 Auflieger für Fähre oder Bahn): jeder
                                 Auflieger wird nur abgestellt, der Auftrag
                                 endet dort
trailer_hub: true                Umschlagplatz (Bahn- oder Fährterminal):
                                 nimmt als ABSENDER beladene Auflieger
                                 zurück, die Rückfracht muss nicht in
                                 seiner in-Liste stehen

    Aufbau ohne Eintrag: curtainside, dryvan, refrigerated, insulated, flatbed, container, flatbed_cont = return_full; jeder andere Aufbau (Tanks, Silo, Kipper, Tieflader, Holz, Viehtransporter, Autotransporter ...) = return_empty. Faustregel: return_full für einen Spezialaufbau nur dort, wo die Firma diesen Aufbau selbst belädt (Steinbruch - Kipper, Sägewerk - Holz, Autoterminal - Autotransporter); Tieflader immer return_empty.

    Rückfracht:

    • geladen, wie der Frachtmarkt des Spiels einen Auflieger belädt, der nicht der Firma gehört: die Fracht muss zum Auflieger passen (Aufbau, Volumen, Gewicht), die ladende Firma muss sie verschicken dürfen (ignore_out, freight_market-Regeln; semi_trailerjob_out gilt nicht, die Firma lädt nur), der Absender muss sie annehmen (seine in-Liste, ignore_in, semi_trailerjob-Regeln), ausser der Absender ist ein trailer_hub
    • zufällig nach den Frachtgewichtungen des Spiels gewählt, fest je Angebot
    • Container: ladende Firma mit container_load: true - der Container wird abgehoben und jede Containerfracht kommt aufs Chassis; mit container_load: false - der Container bleibt, ein Koffercontainer wird mit Fracht seines Aufbaus beladen, ein Spezialcontainer (body_type = Frachtname, siehe Abschnitt 2) nur mit dieser Fracht
    • die Zielfirma gibt nie die Fracht zurück, die sie gerade bekommen hat
    • die ganze Fahrt ist ein Auftrag: eine Lieferzeit beim Absender, bezahlt beim Absender: Hinfracht + Rückfracht; eine Leerfahrt (Ziel - ladende Firma, oder leer zurück) wird wie ein Leercontainer bezahlt: 10 % der Einheiten der Hinfracht je km

    Die Auftragsliste zeigt die Fahrt als Start > Ziel > (2. Firma >) Start, die Rückfracht blau nach der Hinfracht, dazu Gesamtstrecke, -zeit und -lohn. Eine Stadt-Datei kann dieselben Zeilen für eine Stadt enthalten (ein Block in der Stadt-Datei geht für seine Aufbauten vor).

    1e. Wartezeiten¶

    wait_time :
{
load: 30-180
unload: 30-180
pickup: 5-20
drop: 5-15
}
wait_factors :
{
1.5 : (06.00, 08.00);(12.00, 13.00)
0.7 : (22.00, 06.00)
}
    • load = Beladen, unload = Entladen, pickup = Übernahme eines vorbereiteten, beladenen Aufliegers, drop = Abstellen des Aufliegers an einem reinen Abstellplatz (T)
    • Minuten von-bis; bei jeder Anmeldung wird eine Zeit dazwischen gewürfelt
    • wait_factors: Faktor = Zeitspannen (hh.mm oder hh:mm), mehrere Spannen mit demselben Faktor getrennt durch ; ein Ende vor oder gleich dem Anfang läuft über Mitternacht; ausserhalb aller Spannen ist der Faktor 1.0
    • fehlende Zeile oder fehlender Block: Stadt-Datei, dann Firmen-Datei, dann Standard: load/unload 30-180, pickup 5-20, drop 5-15, Faktoren 06-10 x1.5, 16-22 x0.7, 22-06 x0.5
    Die Wartezeit liegt zwischen dem Bestätigen (Wahl der Parkschwierigkeit beim
Abliefern, Enter an der Lade-/Abladespur mit eigenem Auflieger oder die
Lade-Kachel) und der Freigabe von Spur bzw. Auflieger. Bei der Anmeldung zeigt
eine Meldung die erwartete Zeit. Verlassen des Firmengeländes hebt die
Anmeldung auf. Während des Wartens auf dem Gelände anhalten und den Motor
abstellen: ein Hinweis bietet eine Pause bis zum Ende der Wartezeit an. Bei der
Freigabe geht alles von selbst weiter.

    1f. Spuren je Aufbau (Parkschwierigkeit)¶

    Eine Firma kann Spuren einer Schwierigkeit für bestimmte Aufbauten sperren, z. B. keine Tieflader an den Laderampen (schwere Spuren):

    lanes_hard_ignore :          Aufbauten (body_type des Aufliegers, ohne
{                            Präfix), die nie auf einer schweren Spur
lowbed                       laden oder entladen
lowboy
}
lanes_medium_ignore : { ... }   dasselbe für mittlere Spuren
lanes_easy_ignore : { ... }     dasselbe für leichte Spuren
    • gilt für jede Auftragsart bei dieser Firma: Frachtmarkt, Fahreraufträge, Auflieger-Aufträge und Rückfracht
    • Beladen: liegt die Ladespur des Auftrags auf einer gesperrten Schwierigkeit, bekommt der Auftrag eine freie erlaubte Ladespur der Firma (passende Länge, nicht belegt); gibt es keine, bleibt die Spur des Spiels
    • Entladen: gesperrte Schwierigkeiten sind nicht wählbar
    • Frachtmarkt: hat die ladende Firma keine erlaubte Ladespur oder das Ziel keine erlaubte Abladespur für den Auflieger, gibt es kein Angebot dafür
    • es zählt der Aufbau des angekuppelten Aufliegers
    • fest in der DLL, bei allen Firmen: Tieflader (lowbed, lowboy) nur an leichten Spuren; mittlere, schwere und Ladestellen ohne Schwierigkeit (z. B. Rampen) sind für sie immer gesperrt; ausgenommen Umschlagplätze (trailer_hub: true), dort wird nur abgestellt
    • eine Stadt-Datei kann dieselben Blöcke enthalten; sie addieren sich zur Firmen-Datei

    1g. Teilladungen und Tourplanung (Frachtmarkt, eigener Auflieger)¶

    Eine Firma kann im Frachtmarkt Teilladungen anbieten und annehmen:

    units_out :                  Einheiten, die diese Firma je Fracht VERSCHICKT
{
default: 1-max               jede Menge bis zur vollen Ladung
cargo.furniture: 1-6         diese Fracht nur 1 bis 6 Einheiten
cargo.cement: max            diese Fracht nur als volle Ladung
}
units_in : { ... }           dasselbe für das, was diese Firma ANNIMMT

    load_mix_out :               wie oft eine volle bzw. eine Teilladung
{                            angeboten wird (Gewichtung, beliebige Zahlen)
default :
{
full: 60
partial: 40
}
cargo.furniture :
{
full: 20
partial: 80
}
}
load_mix_in : { ... }        dasselbe auf der Empfängerseite
    • Werte: eine Zahl, von-bis (z. B. 1-6) oder max (= volle Ladung)
    • eine cargo.<name>-Zeile geht vor, sonst gilt default
    • eine Stadt-Datei ersetzt in dieser Stadt den ganzen Block der Firmen-Datei
    • kein units-Block bei Absender und Empfänger = nur volle Ladungen wie im Spiel; ein Block nur auf einer Seite = die andere Seite nimmt nur volle Ladungen
    • kein load_mix-Block = volle und Teilladungen halb und halb
    • tour und mixed in load_mix sind für eine spätere Version reserviert
    • eine Teilladung ist weniger als die Mindestfüllung des Aufliegers (cargo_min_fill des Aufbaus in /def/economy_trailers_data/, im Spiel meist 0.8); die Menge ist auf das begrenzt, was noch auf den Auflieger passt
    • Fracht mit load_unit: whole (siehe README der Frachtdaten) gibt es nie als Teilladung

    Zuladen und Tourplanung mit Teilladungen:

    • "Als Navi-Ziel einstellen" bei einem Frachtmarkt-Angebot merkt es vor (auch bevor etwas geladen ist); Annehmen auf dem Firmenhof nimmt es in die Fahrt; höchstens 8 Aufträge und Vormerkungen zusammen
    • jeder Auftrag und jede Vormerkung belegt ihren Anteil an Platz und Gewicht; der Frachtmarkt zeigt dann nur noch Angebote, die zusätzlich passen: Platz, Gewicht, Temperatur / Lebensmittel / Gefahrgut, Lieferzeiten und das Gebiet: ab der zweiten Fracht müssen Absender UND Empfänger eines neuen Angebots je höchstens 100 km (Strasse) von einem Absender oder Empfänger der Fahrt entfernt liegen (auch im Ausland); die erste Fracht ist frei
    • ein voll verplanter Auflieger sperrt den Frachtmarkt, bis ein Teil abgeliefert oder eine Vormerkung storniert ist
    • der aktive Auftrag (Navi) ist die Wahl des Spielers (Rechtsklick auf eine Auftragskachel im Hauptmenü oder "Als Nächstes anfahren" in "Aktueller Auftrag"), sonst das nächste Ziel zuerst, ausser ein anderer Auftrag würde dadurch seine Lieferzeit verpassen
    • Fahrt und Vormerkungen werden mit dem Spielstand gespeichert

    2. Containerfracht¶

    Gleicher Ordner und gleicher Name wie die model_area-Datei der Containerfracht, nur mit .v3def, eine Datei je Containergrösse:

    /def/vehicle/cargo/your_cargo_c/model_area_20.sii
-> /def/vehicle/cargo/your_cargo_c/model_area_20.v3def
/def/vehicle/cargo/your_cargo_c/model_area_40.sii
-> /def/vehicle/cargo/your_cargo_c/model_area_40.v3def
    body_type: dryvanContainer für jede Fracht dieses Aufliegertyps, solange er auf dem Chassis bleibt (dryvan, refrigerated, insulated, oder foodtank für einen Lebensmittel-Tankcontainer)
    body_type: <Frachtname>Spezialcontainer für genau eine Fracht (z. B. Gefahrgut-Tankcontainer - Kraftstoff, Chemikalien, Gas - deren Tafeln zur Fracht gehören): der Aufbau heisst GENAU wie die Fracht (ihre Fracht-.sui und dieser Ordner). Er wird nur wieder mit dieser Fracht beladen, nie von der Firma, die ihn gerade bekommen hat (eine andere Firma belädt ihn, sonst geht er leer zurück). Jeder andere Name steht im Log.
    body_type: nonegar keine Folgefracht: der Container kann nur leer zurückgebracht werden
    body_mass: 2200Leergewicht des Containers in kg
    volume: 33Innenvolumen in m3
    Fehlende Datei oder fehlende Zeile - Standardwerte:
  body_type  dryvan
  body_mass  20 ft 2200 kg, 40 ft 3750 kg  (Kühl: 3000 / 4800 kg)
  volume     20 ft 33 m3,   40 ft 67 m3    (Kühl: 28 / 59 m3)
20 ft oder 40 ft ergibt sich aus der Modellgrösse (länger als 9 m = 40 ft).

    Symbol für "Leercontainer zurück"¶

    Datei: def/vehicle/cargo/<your_cargo_c>/accessory_container_<grösse>_<farbe>.v3def (gleicher Name wie die Accessory-.sii, Endung .v3def)

    empty_icon: "/material/ui/cargo_icons/<your_icon>.mat"

    Die .mat muss in /material/ui/cargo_icons/ liegen (wie jedes Frachtsymbol, 122 x 96 px, transparent). Sie erscheint im Frachtmarkt und in der Auftragsinfo beim Angebot "Leercontainer zurück" dieses Containers. Fehlende Datei - das Symbol der Mod für einen 20 ft / 40 ft Koffer- oder Tankcontainer wird verwendet.

    3. Land-Datei (Fahrerlohn)¶

    Gleicher Ordner und gleicher Name wie die Land-Datei des Spiels, nur mit .v3def:

    /def/country/your_country.sui
-> /def/country/your_country.v3def

    driver_wage :
{
hourly_net_wage: 11.13
daily_allowance: 28
bonus_max: 25
allowance_tier[]: 8 0.5
allowance_travel[]: 0 0.5
}
    • hourly_net_wage: Nettolohn je Arbeitsstunde; eine Fahrer-Tour zahlt höchstens 10 Arbeitsstunden je Kalendertag und 48 Stunden je Tour (eine Tour dauert höchstens 4 Tage + 8 Stunden)
    • daily_allowance: Spesen für einen vollen Tag Abwesenheit
    • die Tour beginnt mit der Annahme und endet mit dem Lieferbericht; Kalendertage in Spielzeit. Volle Tage zwischen dem ersten und dem letzten Tag zählen immer voll. Wie viel der erste/letzte Tag und eine eintägige Tour bekommen, hängt vom Land ab:
    • allowance_tier[]: Stunden Anteil - eintägige Tour (Start und Ende am selben Kalendertag): der Anteil gilt für MEHR als diese Stunden, die höchste passende Zeile zählt; 0 = jede Dauer. Keine Zeile = nichts. allowance_tier[]: 8 0.5 (mehr als 8 h: halber Tag)
    • allowance_travel[]: Stunden Anteil - erster und letzter Tag einer mehrtägigen Tour, Stunden an diesem Tag; fehlt = wie allowance_tier. allowance_travel[]: 0 0.5 (immer halber Tag)
    • allowance_meal[]: hh:mm Anteil / night Anteil - statt Stunden: der Anteil zählt, wenn die Essenszeit an diesem Tag in der Tour liegt, night = eine auswärts verbrachte Nacht (nicht am letzten Tag); höchstens 1 je Tag. Zeilen von allowance_meal ersetzen die Stunden-Zeilen. allowance_meal[]: 13:00 0.333 allowance_meal[]: night 0.334
    • allowance_same_day: 0 = eine eintägige Tour bekommt keine Spesen
    • die Zeilen einer Liste ersetzen die Zeilen der Mod für dieses Land (alle Zeilen dieser Liste, nicht einzelne). Anteile 0 ... 1.
    • keine Spesen = keine Spesen-Zeile im Lieferbericht
    • bonus_max: höchster Lohn über dem Satz in Prozent; jede Startfirma würfelt je Spielwoche ihren eigenen Bonus (die meisten zahlen den Satz), 0 = nie
    • es entscheidet das Land der Firma, bei der die Tour beginnt
    • fehlende Datei oder Zeile: der Wert der Mod für dieses Land gilt (lphd_land_v3def.zip enthält sie für alle Länder)

    Fahrer-Touren (Schnellaufträge) zahlen Lohn und Spesen statt des Frachtlohns. Kraftstoff zahlt der Arbeitgeber (Spiel), Abzüge für Frachtschaden oder Verspätung übernimmt der Arbeitgeber.

    Format¶

    schlüssel: wert

    • ein Eintrag je Zeile, Leerzeichen oder Tabs um den Doppelpunkt erlaubt
    • Zeilen mit # oder // am Anfang sind Kommentare, ein # nach dem Wert auch
    • Zahlen mit Dezimalpunkt, keine Einheiten in der Zeile
    • eine Zeile mit falschem Wert steht im game.log und wird ignoriert

    Beispieldateien¶

    Alle Beispiele zum Herunterladen: resources_company_data.zip

    def/company/your_company.v3def 
    # Fleet & Road Realism - Firmendaten (Standard fuer alle Staedte dieser Firma) / company data (default for all cities of this company)
# Datei / file: /def/company/your_company.v3def  (neben / next to /def/company/your_company.sui)
# Ueber jedem Eintrag steht die Beschreibung (# ...), der Eintrag selbst steht ohne #.
# Above each entry is its description (# ...), the entry itself has no #.
# Alle Moeglichkeiten: README_company_data.txt / all options: README_company_data.txt

# Reachstacker vorhanden? true = Container auf-/absetzen, false = Container bleibt auf dem Chassis
# Reach stacker on site? true = containers are lifted on and off, false = the container stays on the chassis
container_load: false

# Oeffnungszeiten (Spielzeit), fehlender Tag = ganzen Tag offen, closed = geschlossen
# Working hours (game time), missing day = open all day, closed = closed all day
working_time :
{
monday: (06.00, 22.00)
tuesday: (06.00, 22.00)
wednesday: (06.00, 22.00)
thursday: (06.00, 22.00)
friday: (06.00, 22.00)
saturday: (06.00, 12.00)
sunday: closed
}

# Fracht, die diese Firma nie annimmt (cargo.<name> aus der Fracht-.sui, eine je Zeile)
# Cargo this company never receives (cargo.<name> from the cargo .sui, one per line)
ignore_in :
{
cargo.air_mails
}

# Auflieger-Auftraege mit dieser Firma als Ziel: je Aufbau Rueckfracht hier laden (full) oder woanders / leer (empty)
# Trailer jobs with this company as destination: per body type load return cargo here (full) or elsewhere / empty (empty)
semi_trailerjob_return_full :
{
curtainside
dryvan
}
semi_trailerjob_return_empty :
{
fueltank
lowbed
}

# Aufbauten, die nie auf schweren / mittleren Spuren laden oder entladen
# Body types that never load or unload on hard / medium bays
lanes_hard_ignore :
{
lowbed
lowboy
}
lanes_medium_ignore :
{
lowbed
lowboy
}

# Wartezeiten in Minuten von-bis (zufaellig dazwischen)
# Waiting times in minutes from-to (random in between)
wait_time :
{
load: 30-180
unload: 30-180
pickup: 5-20
drop: 5-15
}

# Faktor auf die Wartezeit je Tageszeit (ausserhalb der Spannen 1.0)
# Factor on the waiting time per time of day (outside the spans 1.0)
wait_factors :
{
1.5 : (06.00, 08.00);(12.00, 13.00)
1.3 : (14.00, 15.00)
0.7 : (22.00, 06.00)
}

# Teilladungen: Einheiten, die diese Firma verschickt (Zahl, von-bis oder max = volle Ladung; cargo.<name> vor default)
# Partial loads: units this company sends (number, from-to or max = full load; cargo.<name> before default)
units_out :
{
default: 1-max
cargo.furniture: 1-6
}

# Teilladungen: Einheiten, die diese Firma annimmt
# Partial loads: units this company receives
